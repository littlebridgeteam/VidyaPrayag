## 1. WHAT WE'RE BUILDING

A **Records & Exports** screen accessible from the home tab of both Admin and Teacher portals (mobile + web). The screen lists all available exports, lets the user pick filters (class, date range, status), choose format (PDF or CSV), and download a branded file with school logo, name, and address.

## 2. ENTRY POINTS — WHERE THE BUTTON LIVES

### 2.1 Mobile App (Compose Multiplatform)

#### Admin Portal
- **Home tab** gets a new quick-action card or nav item: **"Records & Exports"**
- Tapping it opens `RecordsScreen` — a full screen listing all 12 export types in categorized sections
- No contextual export buttons on individual screens (keeps it simple, one entry point)

#### Teacher Portal
- **Home/Today tab** gets a new card: **"Records & Exports"**
- Tapping it opens `RecordsScreen` (teacher variant) — shows only the 4 exports available to teachers
- Teacher's exports are auto-scoped to their class/subject — no class picker needed (server enforces)

#### Parent Portal
- **No exports.** Parents consume data, they don't export it.

### 2.2 Web Admin Portal (Next.js)

- **Admin sidebar** gets a new nav item: **"Records"** (icon: a document/download icon)
- Route: `/admin/records`
- Page: `website/src/app/admin/records/page.tsx`
- Full page with all 12 exports, filter controls, format toggle, download button
- Teacher portal on web: same route but scoped to teacher's exports only (role-based filtering)

### 3.4 `server/src/main/kotlin/.../feature/export/ExportService.kt`

**Purpose:** Orchestrator — fetch data + branding → generate file → upload to storage → return URL.

**API:**
```kotlin
class ExportService {
    suspend fun generateExport(
        schoolId: UUID,
        userId: UUID,
        userRole: String,         // "admin" | "teacher"
        request: ExportRequest
    ): ExportResponse

    data class ExportRequest(
        val type: String,         // "student_roster" | "attendance_report" | ...
        val format: String,       // "pdf" | "csv"
        val classId: String?,     // optional filter
        val assessmentId: String?,// for test marks
        val eventId: String?,     // for event registrations
        val routeId: String?,     // for transport
        val homeworkId: String?,  // for homework report
        val status: String?,      // for fees/admissions filter
        val dateFrom: String?,    // YYYY-MM-DD
        val dateTo: String?        // YYYY-MM-DD
    )

    data class ExportResponse(
        val downloadUrl: String,
        val fileName: String,
        val fileSize: Long,
        val format: String
    )
}
```

**Flow:**
1. Validate user has access to requested export type (admin = all, teacher = subset)
2. If teacher: verify class/subject ownership via `TeacherSubjectAssignmentsTable`
3. Fetch `ExportBranding` from DB
4. Fetch data rows via type-specific query (12 `when` branches)
5. If format=pdf → `BrandedPdfExporter.generate(branding, title, subtitle, columns, rows)`
6. If format=csv → `BrandedCsvExporter.generate(branding, title, subtitle, columns, rows)`
7. Upload to Supabase Storage (same `uploadToStorage` pattern as `IdCardService.kt`)
8. Return download URL

**Data queries per type:**

| Type | Query | Columns |
|------|-------|---------|
| student_roster | `SELECT s.student_code, s.full_name, s.class_name, s.section, s.roll_number, s.parent_phone, s.is_active FROM students s WHERE s.school_id = ? [AND class filter]` | student_code, full_name, class, section, roll_number, parent_phone, status |
| attendance_report | `SELECT a.date, s.student_code, s.full_name, s.roll_number, a.status, a.source FROM attendance_records a JOIN students s ON s.id = a.student_id WHERE a.school_id = ? AND a.type = 'student' [AND class/date filter]` | date, student_code, student_name, roll_number, status, source |
| test_marks | `SELECT s.student_code, s.full_name, s.roll_number, m.marks, m.is_absent, m.remark FROM assessment_marks m JOIN students s ON s.student_code = m.student_id JOIN assessments a ON a.id = m.assessment_id WHERE a.school_id = ? [AND assessment filter]` | student_code, student_name, roll_number, marks, is_absent, remark, percentage, result |
| fee_report | `SELECT s.student_code, s.full_name, s.class_name, f.title, f.category, f.amount, f.scholarship_amount, f.status, f.due_date FROM fee_records f LEFT JOIN students s ON s.school_id = f.school_id WHERE f.school_id = ? [AND class/status/date filter]` | student_code, student_name, class, title, category, amount, scholarship_amount, net_payable, status, due_date |
| staff_directory | `SELECT 'Teaching' as type, f.name, f.department, 'Teacher' as role, NULL as phone, NULL as email, f.is_active FROM faculty f WHERE f.school_id = ? [AND homework filter]` | homework_title, subject, class, section, due_date, student_code, student_name, roll_number, status, submitted_at, grade |
| admission_enquiries | `SELECT student_name, parent_name, parent_phone, parent_email, class_name, date, status, source, notes FROM admission_enquiries WHERE school_id = ? [AND status filter]` | student_name, parent_name, parent_phone, parent_email, class_requested, date, status, source, notes |
| event_registrations | Existing `LibraryService.generateExportCsv` pattern — query event_registrations table | parent_name, parent_mobile, student_name, slot_time, attendee_count, status, registered_at |
| leave_requests | `SELECT requester_name, requester_role, class_name, section, date_from, date_to, reason, status FROM leave_requests WHERE school_id = ? [AND date filter]` | requester_name, requester_role, class, section, date_from, date_to, reason, status |
| transport_assignments | `SELECT r.name AS route_name, v.vehicle_number, st.name AS stop_name, s.full_name, s.class_name, s.section, s.parent_phone FROM transport_assignments ta JOIN transport_routes r ON r.id = ta.route_id JOIN transport_vehicles v ON v.id = ta.vehicle_id JOIN transport_stops st ON st.id = ta.stop_id JOIN students s ON s.id = ta.student_id WHERE ta.school_id = ? AND ta.is_active = true [AND route filter]` | route_name, vehicle_number, stop_name, student_name, class, section, parent_phone |
| health_records | `SELECT s.full_name, s.class_name, s.section, h.blood_group, h.allergies, h.chronic_conditions, h.emergency_contact_name, h.emergency_contact_phone, h.doctor_name, h.doctor_phone FROM student_health_profiles h JOIN students s ON s.id = h.student_id WHERE h.school_id = ? ### 10.2 File Naming Convention

Generated files follow this pattern:
```
{export_type}_{class_or_scope}_{date}.{ext}
```
Examples:
- `student_roster_7B_2026-07-12.pdf`
- `fee_report_all_2026-07-12.csv`
- `attendance_7B_2026-07-12.pdf`
- `staff_directory_2026-07-12.pdf`

### 10.3 Storage Path

Files uploaded to Supabase Storage at:
```
exports/{schoolId}/{fileName}
```

With a 24-hour lifecycle (auto-deleted after 24h to save storage). The download URL is a signed URL valid for 1 hour.

### 10.4 Access Control

| Role | Can access | Enforcement |
|------|-----------|-------------|
| Admin (`school_admin`, `school_staff`, `super_admin`) | All 12 exports | `ExportRouting` checks JWT role |
| Teacher | 4 exports only (roster, attendance, marks, homework, leave) | `ExportService` checks `TeacherSubjectAssignmentsTable` for class/subject ownership |
| Parent | None | Route returns 403 |

### 10.5 Error Handling

- Invalid export type → `400 Bad Request` with `{ "error": "Unknown export type: {type}" }`
- Teacher requesting admin-only export → `403 Forbidden` with `{ "error": "You don't have access to this export type" }`
- Teacher requesting class they don't teach → `403 Forbidden` with `{ "error": "You don't have access to this class" }`
- No data found → `200 OK` with `{ "downloadUrl": null, "fileName": null, "message": "No data found for the selected filters" }`
- File generation error → `500 Internal Server Error` with `{ "error": "Export generation failed: {message}" }`
